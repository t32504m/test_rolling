# 栄養制約付きソルバー（作業A）

Python 3.11 以上。リポジトリのルートで導入します。

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

[PuLP](https://coin-or.github.io/pulp/) 3.3.0 と同梱 CBC を使用します。
ライブラリ導入後はネット接続や API キーを使いません。

```python
from solver import solve

plan = solve(
    household={"adults": 2, "children": 1, "days": 3},
    template_id="standard",  # None なら全マスタから通常食・水を選択
    exclude_tags=[],
    exclude_ids=[],
)
print(plan["items"])
print(plan["meta"])
```

`items` の `count` はマスタの `consume_unit` 単位の整数です（箱数ではありません）。
返却順は ID 順。品目マスタ、テンプレート、閾値は呼び出しごとに読み込み、変更しません。
相対パスはこのパッケージを基準に解決するため、実行ディレクトリには依存しません。

## モデル

- テンプレート指定時の候補はそのテンプレートの品目のみです。テンプレートと引数の除外タグ、
  引数の除外 ID を先に適用し、解けない場合も除外を解除したり候補を勝手に追加したりしません。
- 栄養目標・子供係数・上限・多様性はすべて `tests/sanity_config.json` から読みます。
  これらは既存の暫定値であり、本実装で医学的な妥当性や出典を確定したものではありません。
- 食品の購入パック数を非負整数変数にし、エネルギーの下限・上限、1人1日あたりの数量上限、
  各品目の総エネルギーに占める割合、役割別の最低品目数を同時に満たします。
  数量上限は人数×日数に比例し、購入単位への切り上げを許容します。
  多様性は除外後に選べる品目数までとします。
- 目的関数は、テンプレートの `weight × units_per_serving` をエネルギー目標に合わせて
  拡大した理想数量との絶対差（各品目の kcal で重み付け）を最小化します。
  次に、その最適な構成との差を維持したまま余剰エネルギーを最小化します。
  全マスタからの選択では各品目の weight を等しくします。
- 水は食品とは別計算です。候補の水ごとに必要量を満たす最小のボトル数を求め、
  余剰量、weight の降順、ボトル数、ID の順で1品目を選びます。
  既存 `planner.html` と同じく水はケースに丸めません。例えば1人3日の必要量は9Lで、
  W004 の12本ケースに丸めると既存の過剰備蓄チェックに抵触するためです。
- `daily_coeff` のある特別食は通常食の栄養量には加算しません。
  明示的なテンプレートで指定された場合にだけ、マスタの係数・対象人数・日数から別に計算します。
  `template_id=None` は乳児用・介護用・サプリメント等の必要性を推測して自動追加しません。
- **たんぱく質は欠損・null の値を 0g とした下限量で目標を満たします。**
  値を推測してマスタに書き込むことはしません。実際の未知量が非負なら、この下限を満たす解は
  実際の量でも目標を満たします。`meta.protein_constraint` は `"active"`、
  `protein_assumed_zero_ids` は 0g として扱った候補 ID、`total_protein_g` は既知値の合計です。
  既存の `missing_protein_ids` も引き続き返します。
  **品目マスタ全体に非 null のたんぱく質値が1件もない場合だけ**制約を停止し、
  `"missing_data"` を返します。候補から既知値のある品目が除外された場合は制約を停止せず、
  残った候補で下限量を満たせなければ `InfeasiblePlanError` とします。
  データ改訂後は、テスト・常識チェックを再実行してください。

解の最終確認にも `TOLERANCE`（数値計算用の許容幅）を適用し、エネルギーの上下限や
たんぱく質の目標境界で生じる浮動小数点の表現誤差を受け入れます。栄養の閾値自体は変えません。

同じ入力・同じデータ・同じ固定バージョンのライブラリで再現できるよう、候補順を固定し、
CBC は直列探索（`threads=0`、ワーカースレッドなし）・固定乱数種で実行します。
`threads=1` で観測された、探索終了後の約10秒のスレッド待機を避けるためです。
ソルバー実装やデータの版をまたいだ同一解は保証しません。
各最適化段階には30秒の上限を設け、最適性を確認できなければ `RuntimeError` にします。
制約を満たせない場合は `InfeasiblePlanError`（`ValueError` のサブクラス）、
不正な世帯条件や不明なテンプレートは `ValueError` を送出します。
不完全な解や栄養不足の解を成功扱いで返しません。

## 検証

```bash
python3 -m unittest discover -s tests -v
python3 scripts/sanity_report.py
python3 -m unittest solver.test_model -v
```

最後のコマンドは本作業で追加した補足テストです。既存 `tests/` は変更しません。
たんぱく質制約の有効化・実行不可能性・部分欠損の 0g 扱い・全マスタ欠損時のみの停止、
栄養目標の境界での丸め誤差、除外後の実行不可能性、入力検証、購入単位、水量、
対象児童がいない場合の特別食、weight の反映を確認します。
テスト内の人工栄養値はメモリ上のみに置き、品目マスタには書き込みません。
