# 東京備蓄ナビの備蓄量の計算方法（RQ1 の比較対象）

Issue #3 の記録。比較スクリプトの実装はしない（別の Issue で行う）。

## 0. 調べ方と、この記録の確かさ

- 画面の文言は、公開ページの HTML を取得して確認した。
- 計算式は、サイトのフッターの「ソースコード公開」から辿れる東京都の公開リポジトリ（MIT ライセンス）で確認した。
  さらに、公開中のサイトが実際に読み込んでいる JavaScript と照合した。
  - 品目ごとの数量の設定値 39 件は、リポジトリと公開サイトで数値がすべて一致した。
  - 係数 7 と 3、カテゴリの区分、数量の計算式（`Math.ceil(合計 × 係数)`）も、公開サイトのコードに同じものがある。
- さらに、ブラウザ（Playwright + Chromium）でツールを実際に操作した。9 種類の世帯 × 2 種類の住まいの 18 条件で、結果ページの食品の数量を記録した。
  それを、上の式による計算と突き合わせたところ、**18 条件すべてで、食品の全品目が一致した**（3.5）。
- したがって、以下の計算式は推測ではなく、**2026-10-22 時点で公開されているサイトの動作そのもの**である。
  ただし、数値の**根拠**（なぜ 1人1日 3L なのか、など）は、サイトにもリポジトリにも書かれていない（6 章）。

## 2. 利用者が入力する項目

/tool/ では「3つの質問に答えるだけで、あなたのご家庭に合わせた備蓄品目と必要量のリストが表示されます」とある。

| 質問 | 選択肢 | 計算への影響 |
| --- | --- | --- |
| 1. 一緒に住んでいる人数と、それぞれの性別・年代 | 人数 1〜9 人。性別：男性・女性。年代：乳幼児 0〜2歳 / 子供 3歳〜小6 / 子供 中学生以上 / 成人 18歳以上 / 高齢者 65歳以上 | 1人ずつの数量を足し合わせる |
| 2. お住まいの種類 | 戸建て / マンションなど集合住宅 | 係数（3 または 7）が決まる |
| 3. 犬や猫など、飼っている動物がいる | はい / いいえ | ペット用品の表示の有無（数量は出さない） |

- **日数を入力する項目はない。** 日数に当たるものは、質問2の住まいの種類で決まる係数である（3 章）。
- 内部では、年代と性別を組み合わせた 10 区分（`infantsMale` … `agedFemale`）で表す。
  コードのコメントでは `child1` が「子供 3歳~小6」、`child2` が「子供 中学生以上」とされている。
- 食品の数量は、男女で同じ値である（`stockpile.config.js` の全品目で確認）。
  性別が効くのは生理用品と基礎化粧品だけである。

## 3. 数量の計算式

### 3.1 係数（住まいの種類）

`stockpile.config.js` には次の定数がある。

```js
// 上階の係数
export const upStairsRate = 7
// 階下の係数
export const downStairsRate = 3
```

`result.vue` は `isUpstairs ? upStairsRate : downStairsRate` で係数を選ぶ。
画面の選択肢との対応は `ToolStep02.vue` で確認した。「戸建て」が `isUpstairs = false` で係数 3、「マンションなど集合住宅」が `isUpstairs = true` で係数 7 になる。

- **日数との関係**：コード上の名前は「係数」だが、結果ページの表示で日数であることを確かめた。
  戸建てを選ぶと「必要な備蓄の目安 3日分」、集合住宅を選ぶと「必要な備蓄の目安 7日分」と表示される。
  つまり、**係数は日数であり、日数は住まいの種類で決まる**。利用者が日数を選ぶことはできない。
  - 水の説明文の「1日1人3リットルが目安量」とも合うので、`required` は **1人1日あたりの量**と読める。
  - なぜ集合住宅が 7日分なのかの説明は、確認したページにはない（6 章）。

### 3.2 基本の式（大部分の品目）

`result.vue` の「イレギュラーではない品目」の処理は、次の式である。

```
数量 = ceil( Σ（世帯の各人の区分の設定値）× 係数 )
```

- 設定値は `stockpile.config.js` の各品目の `required`（区分ごとの値）である。
- 切り上げは世帯の合計に対して1回だけ行う（1人ずつの切り上げではない）。
- 数量が 0 になった品目は、結果から除かれる。

## 4. 品目のリスト（固定か、入力で変わるか）

- **候補のリストは固定**である。`stockpile.config.js` の `stockpileList` の 62 品目と、ペット用の 5 品目。
  食品等は 16 品目、そのほかは衛生用品・生活用品・女性用品・乳幼児用品・高齢者用品である。
- 入力で変わるのは**数量だけ**で、数量が 0 になった品目が表示から消える。結果、次のように変わる。
  - 乳幼児がいると、ミルクや離乳食などが現れる。
  - 高齢者がいると、おかゆなどが現れる。
  - 乳幼児だけの世帯では、通常の食品の多くが消える。
- 品目を選ぶ仕組み（栄養の釣り合い、好み、調理の可否など）はない。家庭による違いは、年代構成と住まいの種類だけから生じる。

## 5. ページに書かれている出典

- /why/ に「首都直下地震等による東京都の被害想定（令和4年5月25日公表）より」とある。
  これは「ライフラインが当面使えない」「数日程度は流通が機能しない」という**想定される事態**の出典である。
  数量の出典ではない。
- 水の品目の説明文に「1日1人3リットルが目安量」とある。ただし、出典の記載はない。
- それ以外の品目の設定値（レトルト食品 1個/人/日、無洗米 0.375kg/人/日、子供の 0.8 倍など）には、
  サイトにもリポジトリにも出典の記載がない。
- 結果ページには、食物アレルギー対応食品などの特殊食品について、「少なくとも2週間分の食品をご家庭にストックすることをおすすめ」とある。
  ただし、この期間は計算には反映されておらず、出典の記載もない。
- 農林水産省のガイドなど、ほかの資料を出典として挙げた箇所は、確認したページには見当たらなかった。

## 6. 分からなかった点（不明）

1. **設定値の根拠**：各品目の 1人あたりの値（水 3L 以外）と、子供の 0.8 倍、乳幼児の水 2.4L の出典は不明。
2. **集合住宅が 7日分である理由**：結果ページで、戸建ては 3日分、集合住宅は 7日分と表示されることは確かめた（3.1）。
   しかし、なぜ住まいの種類で日数を変えるのかの説明は、確認したページにはない。
   変数名の「上階／階下」から、エレベーターの停止などを想定した区別とも考えられるが、記述がないので不明。
3. **A2 の固定値**：乾麺・お菓子・果物の缶詰が、人数によらず 3（または 6、7、14）である理由は不明。
4. **カロリーや栄養の検討の有無**：計算に栄養の制約は含まれていない。設計の段階で栄養を検討したかどうかは不明。
5. **性別の影響の画面での確認**：ブラウザで確認した世帯には男女の両方が含まれる。しかし、同じ世帯で男女だけを入れ替えた比較はしていない。
   男女で食品の数量が同じであることは、設定値で確かめた。

## 7. 比較スクリプトの仕様案

### 7.1 入力の対応

こちらのソルバーの入力 `{"adults": a, "children": c, "days": d}` を、東京備蓄ナビの入力に次のように写す。

| こちら | 東京備蓄ナビ | 備考 |
| --- | --- | --- |
| adults = a | 成人 a 人 | 男女は食品の数量に影響しないので、どちらでもよい |
| children = c | 子供（3歳〜小6）c 人 | 東京の 0.8 倍は、こちらの `tests/sanity_config.json` の `child_factor: 0.8` と同じ値。中学生以上は成人と同じ扱いなので、こちらの「子供」には当てない |
| days = 3 | 戸建て（係数 3） | |
| days = 7 | 集合住宅（係数 7） | |
| days がほかの値 | **東京備蓄ナビでは表せない** | 基本の式の品目だけ「係数 = days」として外挿する案はある。ただし、それは東京の方式ではなく、こちらの拡張であると結果に明記する。A2 の固定値は外挿しない |

- 比べる世帯条件は、まず **days ∈ {3, 7}** に限るのが安全である。
- 乳幼児と高齢者は、こちらの入力にない。比較の対象外とする（テンプレートとの関係は別途）。
- ペットは扱わない。

### 7.2 出力の対応と比べる量

- 東京の結果のうち、**食品等の 16 品目と水**だけを使う。乳幼児用品・高齢者用品の食品は、該当する世帯だけ使う。
- 「適宜」「適量」の品目（調味料セット、フリーズドライ食品、乾物）は、数量がないので、品目の有無だけを比べる。
- 比べる量（CLAUDE.md の「多様性」と「栄養の条件」）：
  - **多様性**：世帯条件を変えたときに、品目の構成が変わるか。東京は構成が年代構成だけで決まる。
  - **栄養の条件**：東京の結果を、こちらの品目マスタの代表品に置き換えて kcal・水分を計算する。
    `tests/sanity_config.json` の目標値と比べる。1対1に対応しない品目は「対応なし」として、計算から外したことを報告に出す。
